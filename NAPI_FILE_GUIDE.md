# napi — What Every File/Folder Is For (plain language)

This project is a **monorepo** — one repository containing several small programs that work
together, instead of one giant program. Think of it like a house with separate rooms (kitchen,
bedroom, garage) instead of one big open room — each folder has one job.

---

## Top-level files (in the root folder)

| File | What it's for |
|---|---|
| `NAPI_ROADMAP.md` | The full plan — every stage of napi, what's done, what's left. The master to-do list. |
| `NAPI_DEV_NOTES.md` | A running diary of every change made, in order, with reasons. |
| `CONTEXT_HANDOFF.md` | A "catch-up" document — if a new AI session or developer joins, this gets them up to speed fast. |
| `NAPI_INSTALL_GUIDE.md` | Instructions for someone else to install and use the extension — written for a normal person, not a developer. |
| `NAPI_PRESENTATION_PREP.md` | The Q&A doc I just made for your meeting. |
| `NAPI_FILE_GUIDE.md` | This file. |
| `CLAUDE.md` | The ORIGINAL project's (Nanobrowser's) own developer notes — how its code is organized, build commands, etc. Not written by us, but useful reference. |
| `README.md` (and the `README-*.md` translations) | The original open-source project's public description, from before we forked it. |
| `CONTRIBUTING.md`, `SECURITY.md`, `PRIVACY.md`, `AGENTS.md`, `UPDATE-PACKAGE-VERSIONS.md` | Also original project housekeeping files (contribution rules, security policy, etc.) — not things we've changed. |
| `package.json` | The "table of contents" for the whole project — lists every command you can run (like `pnpm build`) and every workspace inside. |
| `turbo.json` | Configuration for the tool that runs build commands across all the little programs efficiently. |

## Top-level folders

| Folder | What it's for |
|---|---|
| `chrome-extension/` | The "brain" — runs in the background, does the actual browsing, thinking, and guiding. This is where almost all of napi's own new logic lives. |
| `pages/` | The things you actually SEE — the side panel, the settings page, and a small helper script that runs on every webpage. |
| `packages/` | Shared building blocks that multiple parts of the project use — like a shared toolbox. |
| `dist/` | The finished, built extension — this is what actually gets loaded into Chrome. Auto-generated by `pnpm build`; never edited by hand. |
| `dist-zip/` | A zipped-up copy of `dist/`, ready to send to someone else to install. Also auto-generated. |
| `node_modules/` | Every external library the project depends on, downloaded automatically. Never touched by hand — this is normal for any JavaScript project. |

## `chrome-extension/` — the brain (this is where napi's own work mostly lives)

| File/Folder | What it's for |
|---|---|
| `src/background/index.ts` | The starting point of the background program. Listens for messages from the side panel ("start this task") and kicks everything off. |
| `src/background/guide-step.ts` | Keeps track of "napi is currently waiting for the user to click this exact thing" — the waiting/watching mechanism behind every guided step. |
| `src/background/agent/executor.ts` | The main loop — runs the Planner, then the Navigator, over and over, until the task is done or fails. |
| `src/background/agent/checker.ts` | **napi's own file.** Decides whether a guided step actually worked, after the user does it. |
| `src/background/agent/helper.ts` | Builds the connection to whichever AI provider you picked (OpenAI, Gemini, etc.) — including the "give up fast if it's broken" and "try a backup" logic. |
| `src/background/agent/agents/navigator.ts` | **The single most important file napi added to.** This is where a normal AI action gets intercepted, turned into a highlighted step, and where napi waits for the user and calls the Checker. |
| `src/background/agent/agents/planner.ts` | The AI that makes the overall plan — mostly original code, with a small addition (see `prompts/`) telling it not to declare things "done" too early in guide mode. |
| `src/background/agent/prompts/` | The actual instructions written for each AI ("you are an assistant that..."). napi added extra instructions here specifically for guide mode. |
| `src/background/agent/actions/` | The list of things the AI is allowed to do — click, type, scroll, go to a URL, etc. |
| `src/background/browser/` | The code that actually talks to the Chrome tab — reading the page, taking screenshots, clicking things. Mostly original Nanobrowser code. |
| `public/buildDomTree.js` | A script injected into every webpage that scans it, numbers every clickable thing, and draws the highlight boxes. napi modified this to fix a highlighting bug on pop-up windows. |
| `manifest.js` | Builds the Chrome extension's "ID card" (`manifest.json`) — its name, permissions, which files to load. |

## `pages/` — the things you actually see

| Folder | What it's for |
|---|---|
| `pages/side-panel/` | The chat panel that opens on the right side of Chrome. This is napi's main interface — where you type requests, see the current step, and run Missions. |
| `pages/options/` | The full settings page (opens in its own tab) — where you add AI provider keys, turn Guide mode on, set up backup models, see your Skill Map, and view Missions in detail. |
| `pages/content/` | A small script that gets injected into every website you visit. Its job: watch for a real click or a real typed value on the highlighted element, and tell the background "the user did it." Also where the Driver.js spotlight visual is drawn. |

### Inside `pages/side-panel/src/`
- `SidePanel.tsx` — the one big file that runs the whole panel: sending messages, showing the chat, running missions, showing the current step.
- `components/CurrentStepCard.tsx` — the colored card that shows "your turn" / "that worked" / "let's try again."
- `components/MissionList.tsx` — the list of pre-written lessons with a Start button.
- `components/NapiLogo.tsx` — the little lightbulb logo shown in the panel.
- `components/ChatInput.tsx`, `MessageList.tsx`, `ChatHistoryList.tsx`, `BookmarkList.tsx` — the typing box, the message bubbles, past conversations, and saved favorite prompts.

### Inside `pages/options/src/`
- `Options.tsx` — the settings page's outer shell (the tab list on the left).
- `components/GeneralSettings.tsx` — the Guide mode on/off switch and other basic settings.
- `components/ModelSettings.tsx` — where you pick which AI model does what.
- `components/FallbackModels.tsx` — where you set up backup AI models.
- `components/SkillMap.tsx` — shows what you've practiced.
- `components/Missions.tsx` — the read-only version of the Missions list (full description + "why" for each step).
- `components/FirewallSettings.tsx`, `AnalyticsSettings.tsx` — original settings (which sites are allowed, usage stats).

## `packages/` — shared building blocks

| Folder | What it's for |
|---|---|
| `packages/storage/` | Everything that gets SAVED and remembered — your settings, your Skill Map, the list of Missions, chat history. Like the project's filing cabinet. |
| `packages/storage/lib/skillMap/` | **napi's own addition.** The Skill Map data and save/load logic. |
| `packages/storage/lib/missions/` | **napi's own addition.** The pre-written lesson content. |
| `packages/storage/lib/settings/` | All the on/off switches and configuration (Guide mode, model choices, fallback list, etc.). |
| `packages/ui/` | Small reusable visual pieces (like a generic Button) shared between the side panel and settings page. |
| `packages/shared/` | Generic helper code (not specific to any one screen) used everywhere. |
| `packages/i18n/` | Translation text — lets the extension show its (original, non-napi) text in different languages. |
| `packages/schema-utils/`, `dev-utils/`, `hmr/`, `tailwind-config/`, `tsconfig/`, `vite-config/`, `zipper/` | Behind-the-scenes developer tooling — build configuration, styling rules, packaging into a zip file. You'll basically never need to open these. |

## The short version, if someone asks "so where's YOUR code, specifically?"

> "The core idea — pause before every click and wait for the user — is in ONE file:
> `navigator.ts`. Checking that it worked is in `checker.ts`. Remembering what the user has learned
> is in `packages/storage/lib/skillMap`. The pre-written lessons are in
> `packages/storage/lib/missions`. Everything else is either the original open-source project's
> existing engine, or the visual side panel that displays all of this."
